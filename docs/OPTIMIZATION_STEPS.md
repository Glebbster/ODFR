# Принятые состояния оптимизатора

Новая сборка сохраняет начальное состояние и принятые состояния **NL2SOL**
в `optimization_steps/fit_000001` внутри текущего каталога расчёта.
Каждый следующий подбор получает свободный номер `fit_000002` и т. д.,
в том числе при повторном запуске программы. Существующие каталоги не затираются.
MINPACK и расчёт без оптимизации этим наблюдателем не охватываются.

`temp*.dat`, `temp*.par`, `history`, входные файлы и конечные результаты
обрабатываются прежним кодом. Наблюдатель не вызывает модель, не меняет параметры,
невязки, критерии сходимости, выбор шага, MPI-обмены или возврат `xbest`.
Использование диска добавляет время записи: нулевые накладные расходы не обещаются.
Записывает только MPI rank 0. При ошибке создания/записи файлов наблюдатель
выводит предупреждение и отключается; оптимизатор продолжает работу.

Отключить запись для запуска в PowerShell:

```powershell
$env:ODFR_OPTIMIZATION_STEPS = '0'
# Запуск программы обычным способом
Remove-Item Env:ODFR_OPTIMIZATION_STEPS
```

## Формат

```text
optimization_steps/
  fit_000001/
    experiment.dat
    step_000000.dat
    step_000001.dat
    ...
```

- `experiment.dat`: номер спектра, поле, исходный экспериментальный сигнал.
- `step_*.dat`: номер спектра, поле, полная модельная кривая; все спектры
  одного состояния находятся в одной таблице. Компоненты отдельных центров
  не дублируются. Значения сохраняются с точностью round-trip для float64.
- Заголовок: `iteration`, номер обычного вычисления `evaluation`, точные
  `SSE_W` и `SSE_UNW` полного подбора, `x_optimizer`.
  Последние — внутренние координаты оптимизатора, **не обязательно физические
  параметры**: существующие преобразования `xpack` остаются в силе.
- Нулевой кадр — исходная точка; остальные — принятые состояния.
  Одинаковая точка повторно не записывается. Номер кадра может отличаться от
  номера итерации. Пробы якобиана, ковариации и отклонённые точки не становятся кадрами.
- Маркер `# complete` завершает полностью записанный кадр. Незавершённую
  последнюю таблицу Python пропускает с предупреждением.

У NL2SOL сохраняется отдельная копия невязки для возврата к прежней пробной
точке. Наблюдатель зеркально сохраняет/восстанавливает **собственные** буферы
спектра в тех же местах; рабочие общие массивы модели он только читает.
Перед записью проверяется совпадение координат принятой точки и снимка.
При несовпадении запись отключается вместо сохранения неверного кадра.

Существующий код после NL2SOL отдельно выбирает `xbest`; его логика не изменена.
Поэтому последний принятый кадр не обязан побитно совпасть с конечным файлом
результата: `xbest` может происходить из другого вычисления, в том числе пробы
численной производной. Такой результат не добавляется под видом принятого шага.

## Память и диск

Буферы наблюдателя: приблизительно `32*N + 24*P` байт, где `N` — сумма
точек всех спектров, `P` — число переменных. История в RAM не накапливается.
При 14 спектрах по 1024 точки это около 0,44 МиБ. При текущем максимуме
20 × 4096 точек — около 2,5 МиБ. Буферы выделяются только на rank 0.

Текстовый кадр занимает примерно `56*N` байт в Windows плюс заголовок:
около 0,8 МБ для 14 × 1024 точек. Диск растёт с числом принятых состояний.
Рисование и сжатие выполняются отдельно, после подбора.

## Python: архив и GIF

Скрипт: `tools/optimization_animation.py`. Для архива нужен NumPy,
для GIF — также Matplotlib и Pillow. Существующая среда
`C:\Projects\SpectraView\.venv\Scripts\python.exe` проверена при разработке;
установка библиотек в ходе этой работы не выполнялась.

Команды ниже запускаются из `ODFR4_3_final`; замените `C:\run` своим каталогом.
Укажите **один** `fit_*`, а не папку со всеми подборами.

Без потери точности:

```powershell
python tools/optimization_animation.py pack C:\run\optimization_steps\fit_000001 C:\run\optimization_steps\exact.zip
```

Компактная копия для просмотра с явно заданной точностью:

```powershell
python tools/optimization_animation.py pack C:\run\optimization_steps\fit_000001 C:\run\optimization_steps\compact.zip --relative-precision 1e-6
```

В компактном режиме первая кривая хранится точно. Для каждого спектра выбирается
единый шаг `q = relative_precision * max(abs(model))` по всей истории. Затем
округляется смещение **каждого полного состояния от первого**:

```text
integer_state[k] = round((model[k] - model[0]) / q)
delta[k] = integer_state[k] - integer_state[k-1]
model_restored[k] = model[0] + q * sum(delta[1:k])
```

Целочисленная сумма точна; ошибка кривой ограничена `q/2` плюс машинное
округление float64, независимо от числа шагов. Это абсолютная граница относительно
максимума амплитуды **каждого спектра**, не относительная ошибка в каждой точке.
При `1e-6` граница равна `5e-7` от пика. Этот режим предназначен для отображения,
а не для повторного научного анализа с исходной точностью.

Нулевые разности хорошо сжимаются ZIP; отдельные индексы разреженной матрицы
не нужны. Архив содержит бинарные NumPy-массивы без pickle, сетку и эксперимент
по одному разу, метаданные всех состояний, точный параметр округления и измеренную
максимальную ошибку. `SSE_W/SSE_UNW` остаются исходными значениями оптимизатора;
по округлённым кривым они заново не вычисляются. Исходные таблицы не удаляются.
Без `--relative-precision` все кривые сохраняются без потерь.

GIF из исходных таблиц или любого из архивов:

```powershell
python tools/optimization_animation.py render C:\run\optimization_steps\compact.zip C:\run\optimization_steps\spectrum1.gif --spectrum 1 --fps 8 --field-unit G
```

`--field-unit` задаёт только подпись оси; преобразования единиц нет. По умолчанию
подпись не предполагает конкретных единиц. Оси фиксированы для всех кадров,
эксперимент неподвижен, между состояниями нет интерполяции. GIF создаётся
покадрово; все растровые кадры одновременно в RAM не хранятся. Рядом сохраняются
PNG и SVG последнего кадра, а также `<имя_GIF>_initial.png` с первым состоянием
на тех же осях. Повторный запуск `render` перезаписывает GIF, оба PNG и SVG
с указанным именем. Исходные таблицы и входной архив не изменяются.

## Проверки

- Сборки GNU Fortran 15.2.0: serial и Microsoft MPI.
- Исходные smoke/HGO-тесты: serial и MPI с двумя процессами.
- Аналитический тест Rosenbrock: одинаковые вычисления и результат при включённом,
  выключенном наблюдателе и ошибке создания папки; исключение отклонённых,
  якобианных и ковариационных проб; сохранение второго спектра с нулевым весом;
  проверка кривых по параметрам; отсутствие перезаписи предыдущего подбора.
- `tests/optimization_steps/check_archive.py`: восстановление float64 без потерь,
  проверка границы ошибки каждого компактного кадра, неизменность исходных таблиц.

Тестовый пример HGO (145 состояний × 1024 точки): исходные таблицы около 8,4 МБ,
архив без потерь около 1,22 МБ, компактный архив при `1e-6` около 0,22 МБ.
Это измерение конкретного примера, а не универсальный коэффициент сжатия.
